# v9.4 — bezpečné účty a serverová ekonomika

## Stav nasazení

Databázové změny jsou aplikované v Supabase projektu `vfbdsclqvsjbzzhyaegw`. Klient v tomto pracovním adresáři používá verzi 9.4. GitHub Pages začne nový klient používat až po publikování této revize repozitáře; samotná SQL migrace klienta neaktualizuje. Starý klient nesmí znovu dostat právo zapisovat chráněná ekonomická pole.

Historické SQL soubory v `docs/supabase/` zachycují skutečně aplikované změny. Pořadí pro nové prostředí po původním schématu: `security_hardening_2026_11_03.sql`, `account_commands.sql`, `account_commands_followup.sql`, `account_blackjack.sql`, `account_announcements_public.sql`, `account_wallet_audit.sql`, `account_command_limits.sql`, `social_author_ids.sql`, `slot_partial_payout.sql`, `account_replay_state.sql`. Nejsou určené k opakovanému spouštění v již migrované produkci. Starší `schema_update_v6.5.sql` ani `schema_update_v9.2.sql` nepoužívat k přepsání aktuálních funkcí a oprávnění.

## Výsledné chování

- Supabase Auth ověřuje relaci; lokální profil a `sb_jwt_*` řetězec nemají autorizační význam. Offline přihlášení a přenos hostovského zůstatku do registrovaného účtu jsou odstraněné.
- Nákup, denní bonus, kolo, automaty, dostihy a blackjack mají serverové ceny, výsledky a vypořádání. Požadavek má UUID, opakování stejné operace nevyplácí podruhé. Řádkové a transakční zámky chrání současné operace dvou zařízení.
- Blackjack drží balíček a skrytou kartu na serveru, podporuje split, double a obnovu rozehrané ruky. UI pouze vykresluje potvrzený stav.
- Adopt Me používá serverové cooldowny, ceny a vážené fondy vajíček. Obecný sync již nepřepisuje inventář ani postup.
- Soukromé zprávy, přátelství, účtenky a historie ekonomiky jsou v neveřejných tabulkách. Obsah zpráv se nevysílá veřejným Realtime broadcastem. Administrátorská oznámení mají veřejné čtení, ale zápis pouze ověřenou administrátorskou funkcí.
- Profilové změny používají revize. Opožděná odpověď z předchozího účtu nebo starší revize nesmí přepsat novější stav. Sociální cache se při změně účtu vyčistí.
- Síť používá jeden připravený přenos, pořadí pozičních zpráv a omezené fronty. Pro kolize přibyl prostorový index; uvolňování 3D zdrojů je společné a zachovává sdílené cache.

## Změna odměn za klientské minihry

Klientská fyzika nedokáže bezpečně prokázat výhru nebo zabití protivníka. Přihlášené účty proto získávají omezenou účastnickou odměnu 20 B$ nejdříve po 30 sekundách a maximálně 600 B$ na relaci, místo přijetí libovolné klientské částky. Casino je z těchto odměn vyřazené. Nejde o úplnou ochranu proti podvádění: polohu, fyziku, NPC a splnění prostorových úkolů nadále simuluje klient. Pro soutěžní autoritu je potřeba samostatná serverová simulace. Hostovský režim zůstává lokální zkoušení her.

## Alternativní Node backend

Před spuštěním nastavit náhodný `JWT_SECRET` s alespoň 32 znaky. Administrátora určuje `ADMIN_USER_ID`, nikoliv jméno. Případné další originy uvést do `ALLOWED_ORIGINS`; produkční nasazení má používat HTTPS a `NODE_ENV=production`. `BOBLOX_DB_PATH` může SQLite uložit mimo adresář aplikace. Server zveřejňuje pouze frontendové cesty, nikoliv kořen repozitáře. Testy používají izolované databáze a testovací klíče.

## Ověření a zbývající omezení

`node --test` ověřuje načtení společného prohlížečového prostoru, reálné HTTP/SQLite operace, opakování a souběžné nákupy, skrytá pravidla blackjacku, soukromé operace a kolizní kandidáty vůči přesným kolizím. `test/supabase-account-security.sql` ověřuje živý Postgres s následným ROLLBACK, včetně čtení zprávy příjemcem na jiném zařízení a zákazu čtení třetím účtem.

Ovládání prohlížeče v této relaci selhalo při inicializaci místního prostředí; vizuální kontrola na PC/mobilu není tímto reportem potvrzená. Změny zachovávají DOM ID a stávající rozložení.

Dva historické profily bez odpovídajícího Supabase Auth účtu potřebují ověření vlastníka a bezpečný převod; jejich původní hashe jsou zachované v neveřejné tabulce. Nelze je bezpečně spojovat jen podle jména či dříve veřejného hashe. Ochranu proti uniklým heslům je potřeba zapnout v nastavení Auth, pokud to tarif umožňuje; připojené MCP nástroje tuto konfiguraci neupravují.

Security Advisor upozorňuje na záměrně dostupné autentizované SECURITY DEFINER funkce a na neveřejné tabulky s RLS bez povolujících politik. Funkce mají vlastní ověření uživatele/oprávnění; privátní tabulky mají být pro klienty nepřístupné. Nové indexy mohou do prvního využití vykazovat informační hlášení o nepoužití.

Kontrola závislostí odstranila zranitelnost body-parser aktualizací na 2.4.0 v package-lock.json; produkční npm audit po opravě hlásí nula známých zranitelností.

Při přepnutí účtu se rozpracovaný RPC požadavek drží původního ověřeného tokenu; odpovědi předchozího účtu se do nové relace neaplikují.
